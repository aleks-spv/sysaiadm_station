# Linux: общие правила

## Разведка (первым делом)
- `uname -a`
- `cat /etc/os-release`
- `df -h`
- `free -m`
- `systemctl --failed`
- `journalctl -p err -n 50 --no-pager`

Разведка только читает. Ничего не меняй, пока не собрал картину.

## Неинтерактивный режим
- Всегда `--no-pager` для `journalctl`, `systemctl`, `git`.
- `DEBIAN_FRONTEND=noninteractive` перед apt-командами.
- `-y` только если пользователь явно разрешил установку или удаление.
- Не запускай команды, которые ждут TTY.

## Запрещено
- Редакторы и пейджеры: `vim`, `vi`, `nano`, `less`, `more`, `man`.
- `top` и `htop` без `-b` и `-n 1`. Используй `top -b -n 1 | head -20`.
- `sudo` без `-n`. Если нужен пароль, команда не выполняется — сообщи об этом.

## Привилегии
- `sudo -n <команда>`. Если `sudo -n` падает с просьбой пароля, остановись и сообщи.
- Не передавай пароли в `sudo -S` или через pipe.

## Правка конфигов
1. Бэкап перед любой правкой: `cp -a /etc/<файл> /etc/<файл>.bak-$(date +%Y%m%d%H%M%S)`.
2. Правь файл целиком через `tee` или heredoc, без `sed -i` на сложных местах:
   ```
   sudo -n tee /etc/<файл> >/dev/null <<'EOF'
   ...содержимое...
   EOF
   ```
3. Проверка после правки, до перезапуска сервиса:
   - nginx: `sudo -n nginx -t`
   - sshd: `sudo -n sshd -t`
   - прочее: найди штатный тест конфига для сервиса.
4. Перезапуск сервиса только после успешной проверки.

## SSH и доступ
- Не перезапускай `sshd` без `sshd -t`, иначе можно потерять доступ.
- Не меняй правила фаервола (`iptables`, `nft`, `ufw`), не проверив, что SSH-порт остаётся открытым. Такие команды помечаются как опасные и требуют подтверждения.

## Сервисы
- Статус: `systemctl status <сервис> --no-pager -l`
- Логи сервиса: `journalctl -u <сервис> -n 100 --no-pager`
- `stop`, `disable`, `mask`, `restart` — опасные, подтверждение обязательно.

## Отчёт
- Что проверено, с выводом команд.
- Что изменено, и где лежит бэкап.
- Что не проверено.
